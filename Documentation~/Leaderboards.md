# Лидерборды

Первая версия — общий контракт, модели, `LeaderboardProviderBase` и безопасный
`UnsupportedLeaderboardProvider`. Адаптеров SDK пока нет: для всех платформ
Static API и VContainer предоставляют заглушку с `IsSupported = false`.

## Три операции

| Метод | Назначение |
| --- | --- |
| `SetScore(id, score, ...)` | Отправить результат текущего игрока |
| `Fetch(id, ..., limit: 10)` | Получить топ таблицы |
| `FetchCurrentPlayerEntry(id, ...)` | Получить рекорд и позицию текущего игрока |

`id` — строковый идентификатор таблицы игры. Его соответствие площадке задаёт
будущий адаптер: техническое имя, поле счёта или другая настройка SDK.
Типы SDK в контракт не попадают.

```csharp
var leaderboards = UniWebBridge.Leaderboards;
if (!leaderboards.IsSupported || !leaderboards.IsReady) return;

leaderboards.Fetch("score", result =>
{
    foreach (var entry in result.Entries)
        UnityEngine.Debug.Log($"{entry.Rank}: {entry.DisplayName} — {entry.Score}");
}, error => UnityEngine.Debug.LogWarning(error), limit: 10);

leaderboards.SetScore("score", 1500, result =>
{
    if (result.IsConfirmed)
        UnityEngine.Debug.Log("Запись подтверждена платформой");
});

leaderboards.FetchCurrentPlayerEntry("score", entry =>
{
    if (entry != null)
        UnityEngine.Debug.Log($"Мой рекорд: {entry.Score}");
});
```

Через VContainer получите `ILeaderboardProvider` после `builder.RegisterUniWeb()`.

## Данные и поведение

- `LeaderboardEntry`: строковый `PlayerId`, `DisplayName`, `AvatarUrl`, числовой
  `Score`, nullable `Rank`, `IsCurrentPlayer` и необязательные `ExtraData` / `FormattedScore`.
- `Rank` начинается с 1; неизвестная позиция — `null`. Отсутствующие имя,
  ID и аватар — пустые строки. ID не выводится из имени или позиции.
- `LeaderboardResult` — неизменяемый снимок топа. Он копирует переданный список;
  последующие изменения источника не меняют уже полученный результат.
- Успех `Fetch` с пустым списком — пустая таблица. Успех
  `FetchCurrentPlayerEntry` с `null` — записи игрока нет. Ошибка запроса
  передаётся через `onError`, а не маскируется под отсутствие рекордов.
- Сортировку, правила обновления рекорда и единицы счёта задаёт таблица игры.
  Пакет не выбирает максимум автоматически: для времени меньший результат может быть лучше.
- `Score` имеет тип `decimal`: обычные `int` и `long` передаются напрямую,
  дробное значение — например, `12.5m`. Это позволяет сохранить целые числа и
  дроби без привязки к числовому типу SDK. Адаптер обязан отклонить неподдерживаемый
  диапазон или точность через `InvalidArgument`, а не обрезать значение.
- Для времени удобно выбрать целые миллисекунды. `FormattedScore` сохраняет
  готовое представление, если оно есть; иначе отображение определяет игра.
- `extraData` — необязательная строка, например JSON игры. Если площадка её
  не поддерживает, адаптер сообщает `Unsupported` вместо тихой потери данных.
- `SetScore` не означает «сохранить только лучший». Сравнение с текущим рекордом
  при необходимости делает игра; чтение и последующая запись не являются атомарной операцией.
- `LeaderboardSubmitResult.SubmittedScore` — отправленное значение, не итоговый
  рекорд. `IsConfirmed = true` допустим только при подтверждении записи платформой.
  Если SDK позволяет лишь передать команду, возвращается `false`; заглушка
  никогда не вызывает callback успеха.

`IsSupported` означает наличие функции, `IsReady` — готовность SDK,
`IsBusy` — наличие незавершённой операции. Все вызовы и callbacks выполняются в
главном потоке Unity. Callback может сработать синхронно. Будущий адаптер должен
вызвать только один завершающий callback, проверять `limit >= 1` и ограничения
площадки, а при недоступной операции возвращать ошибку.

## Расширение

Наследуйте `LeaderboardProviderBase` и переопределите поддерживаемые операции.
Базовые методы завершаются через `Unsupported`, после `Dispose` — через `Disposed`.
Заглушка безопасна и при вызове без callbacks.

Для Static API отключите `AutoInitializeStaticAPI` и передайте свой объект:

```csharp
UniWebBridge.Initialize(leaderboards: myLeaderboards);
```

Замена освобождает предыдущий провайдер; повторная передача того же экземпляра
его сохраняет. Существующие вызовы `Initialize` совместимы с новым параметром.
В VContainer зарегистрируйте свою реализацию после `RegisterUniWeb()`.

Базовый класс не создаёт запросов и подписок. Будущий адаптер сам управляет
своими запросами: снимает подписки до пользовательского callback, завершает
ожидающие callbacks ошибкой `Disposed` при освобождении и не выдаёт поздний
ответ за результат следующего запроса. Общие события SDK могут потребовать
сериализации операций между экземплярами. Автоматической авторизации и повторной
отправки рекорда нет.

## На чём основан контракт

[PluginYG2](https://max-games.ru/plugin-yg/doc/lb/) предоставляет запись результата
с `extraData`, чтение таблицы и данные текущего игрока. Его API записи использует
`int` и не возвращает подтверждение сохранения. Ограничения типа и частоты запросов
должен учитывать будущий адаптер.

[GamePush](https://docs.gamepush.com/docs/leaderboards/leaderboard/) строит таблицы
на числовых полях игрока, возвращает топ и позицию игрока; также имеет нативный
overlay. Эти различия учтены на уровне контракта и не требуют SDK в игровом коде.
Соседи по рейтингу, нативное окно, фильтры и пагинация в первую версию не включены.
